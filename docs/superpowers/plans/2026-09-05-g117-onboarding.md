# G117 — first-run onboarding: owner identity + first-run sheet + demo bank — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A fresh install stops landing on an empty, unexplained Graph tab. The person types their
name once (`GET/PUT /settings/owner`), which finally makes `settings.observer_owner` — already read
by `inbox_service._owner_observer` but hardcoded everywhere else — the ONE value every user-stated
claim carries, and marks their own entity page so the app can render it as "Name (you)" instead of a
literal `rodrigo`. A four-step first-run sheet (identity → engine → one capture channel → first
Sleep) replaces today's single-step Connect guide. Every tab that can be empty says so honestly with
one action. A checked-in synthetic demo-bank generator lets the sheet offer "try it on a demo bank
first" so the graph is never blank. Three small, verified install/copy gaps ship alongside.

**Architecture:** Backend adds one new module (`api/services/owner_identity.py` — owner.json +
entity-page write + the resolution precedence) and one new router (`api/routers/settings.py`),
touches four existing observer-literal sites plus `GraphNode`, and adds `api/services/demo_bank.py`
+ `POST /banks/demo`. App adds `Views/Onboarding/FirstRunSheet.swift` (composing the already-shipped
`EngineCard`/`IntegrationsView`), a shared `EmptyStateView`, and a small, contained fix to how the
app recognizes "the owner" in claim data (Task 2) — without it, Task 1's backend fix silently
mislabels every future user-stated claim as "External" in the graph, the claim chips, and the
observer filter, which would make G117 worse than doing nothing app-side.

**Tech Stack:** Python 3 / FastAPI / Pydantic (`api/`), SwiftUI + XCTest (`app/CicadaApp`),
markdown + git bank.

**Spec:** G117 row (`docs/goals/memory-evolution.md`), CLAUDE.md's "Unified inbox" → *Open observer
inconsistency* paragraph, G122/G126 (Track C, PR #60, reused wholesale here), G130 (font rule).

## Rulings (binding — filling the gaps the brief left open)

- **R1 — the observer-owner resolution precedence, and its migration-safety rung.**
  `owner_identity.resolve_observer(memory_path, settings)`:
  1. `settings.observer_owner` (existing `CICADA_OBSERVER_OWNER` env field) if non-empty — unchanged,
     an explicit dotfile override always wins.
  2. `~/.cicada/owner.json`'s `entity_id`, once onboarding has run.
  3. The legacy literal `"rodrigo"` **only if** `entities/rodrigo.md` already exists in THIS bank —
     the exact migration-safety check the brief calls for: an install that predates G117 keeps its
     one existing lineage untouched until the person explicitly sets their name, at which point the
     resolved slug simply becomes the id of whatever page their name slugs to (which IS `rodrigo.md`
     if they type "Rodrigo" — no fork, no dangling second page).
  4. Otherwise (a genuinely fresh bank — the demo bank, a brand-new install, before onboarding runs):
     the fixed portable keyword `"owner"`. Never a name, never blank.
  This function REPLACES the read at all five sites (`inbox_service._owner_observer` becomes a thin
  delegate so no caller's behavior changes shape, only its source of truth).
- **R2 — the app renders "the owner" generically, not the literal `rodrigo` (Task 2 exists because
  of this ruling).** Because R1's resolved value can be `"owner"`, `"rodrigo"`, or a name-derived slug
  like `"bob-example"`, and the wire protocol's only OTHER reserved keywords are `"agent"` and the
  `"external:"` prefix, **any observer string that is not `"agent"` and does not start with
  `"external:"` is, by construction, the owner** — a closed-set-by-elimination rule that needs zero
  new plumbing (no fetching "who is the owner" into the app at all): `Observer.init(wire:)`'s default
  case becomes `.rodrigo` (kept as the Swift symbol name — renaming is cosmetic churn with no
  behavior change and is left alone) instead of `.external(wire)`; `ObserverFilterBar`'s "You" segment
  and `GraphViewModel.setObserver` gain a `"__owner__"` sentinel handled exactly like the existing
  `"external"` roster-filter branch (`GraphViewModel.swift:384-391`); `graph.js`'s
  `observerBadgeColor` gets the same not-agent-not-external fallback instead of a literal-keyed
  lookup.
- **R3 — the owner entity page is created/updated at the RESOLVED slug only; a pre-existing page
  under a different id is never renamed or merged.** If `entities/rodrigo.md` already exists and the
  person types a different display name during onboarding, `PUT /settings/owner` creates a SEPARATE
  new page at the new slug and marks IT `owner: true` — it does not touch, rename, or delete the old
  page. Reconciling that (a genuinely different, harder problem — entity merge across an identity
  change) is out of scope; R1's rung 3 exists precisely so the common case (the person types the same
  name the bank already used) never needs it.
- **R4 — step 2 embeds `IntegrationsView()` whole, not a hand-filtered subset.** Its three internal
  row types are `private` to that file; carving out a "just these four rows" component would mean
  either a visibility change plus a second layout, or a second, drifting implementation of channel
  rows. `IntegrationsView` already reads live `Store` snapshots and is short (280 lines) — embedding
  it as-is inside the wizard step, with one caption line above it ("Connect one thing to get started
  — you can add the rest anytime in Settings → Integrations"), satisfies "one capture channel"
  functionally (the person picks one row to connect) without a second component to maintain.
- **R5 — `hasOnboarded` is a plain per-bank `UserDefaults` dictionary, not `@AppStorage`.** No
  existing dynamic-key precedent exists (R5's alternative — a fixed `@AppStorage` key holding a
  `Set<String>` of onboarded bank names — works too, but a small `OnboardingState` enum with static
  `func isOnboarded(bank:) -> Bool` / `func markOnboarded(bank:)` reading/writing
  `UserDefaults.standard` under key `"cicada.hasOnboarded.\(bank)"` is simpler to unit-test and mirrors
  `UsageViewModel`'s existing plain-`UserDefaults` pattern (`UsageViewModel.swift:20,67`) more closely
  than inventing a new `@AppStorage`-of-a-Set shape.
- **R6 — the first-run sheet triggers on "active bank has zero entities AND not yet onboarded",
  checked from `store.status`/healthz, never a second network call.** `HealthResponse.entity_count`
  (`schemas.py:1040`) is already fetched at boot; the sheet's trigger reads
  `store.graph.value?.nodes.isEmpty` (already hydrated by `store.bootstrap()`) rather than issuing its
  own request — consistent with "the sheet reads Store snapshots, never blank."
- **R7 — the demo bank is fully deterministic, no LLM, no randomness.** ~60 entities, ~40 episodes, 6
  inbox items are hand-authored Python literals (not templated/randomized), so `test_demo_bank.py` can
  assert exact counts and exact ids. It reuses `owner_identity.ensure_owner_entity` for its own
  placeholder owner (`bob-example`), so the demo bank and a real onboarded bank produce byte-identical
  owner-page shape — one code path, one thing to keep correct.
- **R8 — the byok failure-message fix keys off `engine_detail`, not a new "was anything configured"
  probe.** `_stage1_failure_message` already receives everything it needs; the fix is a three-line
  branch using the exact signal `engine_select.py` already emits (R8 avoids inventing a second way to
  ask "did anyone choose an engine").

```python
"""G117 — owner identity: one machine-global file (`~/.cicada/owner.json`)
naming the person, and the one function every claim-writing site resolves
"who is the owner" through.

Two things this module deliberately keeps separate:

* `owner.json` — a machine-global USER CHOICE, same class of file as
  `connections.json` (registry.py's `PREFS_FILE_NAME` pattern: `cicada_home()`,
  0600, plain JSON) — never a bank file, never a secret (name/handle/email
  only; CLAUDE.md's rail).
* the owner ENTITY PAGE — a per-bank `entities/<slug>.md`, created the first
  time `ensure_owner_entity` runs against a given bank, marked `owner: true`
  so `GET /graph` can flag the node (see `graph_builder.py`) and the app can
  render "Name (you)".

`resolve_observer` (R1) is the single function that replaces the hardcoded
literal `"rodrigo"` at every one of the five sites CLAUDE.md's "Open observer
inconsistency" paragraph names (`inbox_service._owner_observer`,
`telegram_capture.py`, `agentic_write.write_claim`'s two checks, and
`mcp/server.py`'s tool schema/handler). ONE resolution, called everywhere,
is what keeps a bank's claim lineage from forking — the exact failure mode
`inbox_service.py`'s pre-existing `TODO(G117)` warns about.
"""
from __future__ import annotations

import json
from datetime import date
from pathlib import Path

from api.config import Settings
from api.services import decay_policy, entity_body, markdown_parser
from api.services.auth import cicada_home
from api.services.id_utils import sanitize_id
from api.models.schemas import DecayClass

OWNER_FILE_NAME = "owner.json"
# R1 rung 4 — a fresh bank (no owner.json, no legacy `rodrigo.md`) resolves
# here: a portable keyword, never a name, never blank. Anything that isn't
# "agent" or "external:*" reads as the owner on the app side (R2), so this
# keyword renders correctly with zero app-side plumbing.
DEFAULT_OBSERVER = "owner"
LEGACY_OBSERVER = "rodrigo"


def owner_json_path() -> Path:
    return cicada_home() / OWNER_FILE_NAME


def load_owner() -> dict:
    try:
        return json.loads(owner_json_path().read_text(encoding="utf-8"))
    except (OSError, ValueError):
        return {}


def save_owner(data: dict) -> None:
    path = owner_json_path()
    path.write_text(json.dumps(data, indent=2) + "\n", encoding="utf-8")
    path.chmod(0o600)


def resolve_observer(memory_path: Path | None, settings: Settings | None = None) -> str:
    """R1 — the value every user-stated claim's `observer=` should carry.

    Precedence: an explicit `CICADA_OBSERVER_OWNER` env value (unchanged,
    power-user override) > `owner.json`'s `entity_id` (set by
    `PUT /settings/owner`) > the legacy literal `"rodrigo"`, but ONLY when
    THIS bank already has that page (an install that predates onboarding
    keeps its one lineage rather than forking) > `DEFAULT_OBSERVER` for a
    genuinely fresh bank. Never raises — a corrupt owner.json reads as
    "nothing set", matching every other prefs reader in this codebase
    (`connections/registry.py`'s `prefs()`).
    """
    if settings is not None:
        env_val = str(getattr(settings, "observer_owner", "") or "").strip()
        if env_val:
            return env_val
    entity_id = str(load_owner().get("entity_id") or "").strip()
    if entity_id:
        return entity_id
    if memory_path is not None and (Path(memory_path) / "entities" / f"{LEGACY_OBSERVER}.md").exists():
        return LEGACY_OBSERVER
    return DEFAULT_OBSERVER


def ensure_owner_entity(memory_path: Path, name: str) -> tuple[str, bool]:
    """Create-or-update the owner's `person` page at `sanitize_id(name)`.

    R3: never touches a page under any OTHER slug, even one that is clearly
    "the same person" under an older name — that reconciliation is a
    separate, harder problem (entity merge) and out of this row's scope.
    Evergreen (CLAUDE.md's decay-class rail: reserved for ingest writers and
    the user — a direct `PUT /settings/owner` from onboarding is a user
    write) — the owner's own page does not decay for being unmentioned.
    """
    memory_path = Path(memory_path)
    entities_dir = memory_path / "entities"
    entities_dir.mkdir(parents=True, exist_ok=True)
    entity_id = sanitize_id(name)
    filepath = entities_dir / f"{entity_id}.md"
    today = str(date.today())

    if filepath.exists():
        parsed = markdown_parser.parse(filepath)
        parsed.frontmatter["owner"] = True
        parsed.frontmatter["name"] = name.strip() or parsed.frontmatter.get("name", entity_id)
        markdown_parser.write(filepath, parsed.frontmatter, parsed.body)
        return entity_id, False

    frontmatter = {
        "name": name.strip() or entity_id.replace("-", " ").title(),
        "type": "person",
        "status": "active",
        "confidence": 1.0,
        "created": today,
        "last_referenced": today,
        **decay_policy.frontmatter_fields(DecayClass.evergreen),
        "source_episodes": [],
        "tags": ["owner"],
        "related": [],
        "version": 1,
        "layout_version": 2,
        "owner": True,
    }
    body = entity_body.compose_body_v2(
        summary=f"{frontmatter['name']} — this bank's owner.",
        key_facts=[], history_entries=[], related=[], links=[], open_questions=[],
    )
    markdown_parser.write(filepath, frontmatter, body)
    return entity_id, True
```

```swift
/// G117 — one honest "nothing here, here's the one thing to do" component,
/// reused by every tab that can be empty on a fresh bank (Graph, Inbox,
/// Feed, Sources — Sleep's own desk already handles zero, G125). The
/// bookworm at `.happy` reads as reassurance, not an error.
///
/// Two action shapes, not one, because a PLAIN closure cannot reliably open
/// the Settings window on this app's target OS: `SidebarView.swift`'s own
/// `SettingsGearButton` docstring records measuring `NSApp.sendAction(
/// Selector(("showSettingsWindow:")))` as *accepted and silently ignored* on
/// macOS 26 — `sendAction` returns `true`, no window appears — which is why
/// that button is built from `SettingsLink` (a `View`, not a callable
/// action) rather than a `Button` with an imperative body. `settingsSection`
/// renders that same `SettingsLink`, pre-seeding which section it opens to
/// via a `.simultaneousGesture` (runs alongside `SettingsLink`'s own
/// built-in action, not instead of it) — the moment ANY empty state needs to
/// send the person to Settings, it must use this path, never a bare
/// `action:` closure that calls `openSettings()` or the AppKit selector
/// directly.
struct EmptyStateView: View {
    let title: String
    let message: String
    var actionLabel: String? = nil
    var action: (() -> Void)? = nil
    /// Set instead of `actionLabel`/`action` when the one thing to do is
    /// "open Settings, on this section."
    var settingsSection: SettingsSection? = nil

    var body: some View {
        VStack(spacing: CicadaTheme.spacingLG) {
            BookwormView(state: .happy, pointSize: 96)
            Text(title).font(CicadaTheme.headingFont).foregroundStyle(CicadaTheme.textPrimary)
            Text(message)
                .font(CicadaTheme.bodyFont).foregroundStyle(CicadaTheme.textTertiary)
                .multilineTextAlignment(.center).fixedSize(horizontal: false, vertical: true)
            if let section = settingsSection, let actionLabel {
                SettingsLink { Text(actionLabel) }
                    .buttonStyle(.cicadaPlain).foregroundStyle(CicadaTheme.accent)
                    // Seeds the section `SettingsScene.onAppear` reads
                    // (`:19,34` — the same `@AppStorage("cicada.settingsSection")`
                    // key it already persists to) BEFORE the link's own
                    // built-in action opens the window, so it opens
                    // straight to Integrations instead of wherever Settings
                    // was last left.
                    .simultaneousGesture(TapGesture().onEnded {
                        UserDefaults.standard.set(section.rawValue, forKey: "cicada.settingsSection")
                    })
            } else if let actionLabel, let action {
                Button(actionLabel, action: action)
                    .buttonStyle(.cicadaPlain).foregroundStyle(CicadaTheme.accent)
            }
        }
        .frame(maxWidth: 360)
        .frame(maxWidth: .infinity, maxHeight: .infinity)
    }
}
```
