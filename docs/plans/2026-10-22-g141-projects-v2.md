# G141 projects v2 — born from a repository or the person's words; standard sections (ruling 36 D4)

Branch `feat/projects-v2`, against `dev`. Backend and wire only; the SwiftUI page is specced in
`docs/architecture/app.md` (*Projects v3*) and needs a Mac.

## Global constraints

- No model at the birth decision; no new capture data; the backend never opens, stats or runs git in a stored path
  (G110 D2). The hook reads no remote, so the repository's name is its folder name (disclosed deviation from the
  ruling's wording).
- `progress.py` stays the only writer of events; backlogs stay their own files (G150); looks stay `design_refs`'.
- Promotion is unchanged for every type but `project`.
- Nothing archived or deleted; the dry run writes nothing; the review list waits for the owner.
- Evidence is a span, never a copy (G118); a model's JSON can never carry its own birth record.

## Rulings

1. **R-PV1 — two origins, one record.** `born: {origin: repo|words, day, episode, repo?, span?, via?}`, written once by
   Stage 5's create branch from Stage 2's change (`project_birth` on the change), and by `folder_source.ensure_project`
   (`words, via: folder`: the person typed the name).
2. **R-PV2 — repo.** An episode with `workspace_identity.family_hash` whose `cwd_hash` is the stored `project_dir`'s,
   and the mention's name/alias folded equal to the path's last component or the one before `.worktrees`/`worktrees`.
3. **R-PV3 — words.** A person's turn (`promotion.PERSON_KINDS`), one sentence, name and a project word (six languages,
   plural) in one clause (no `, ; : ( )` between), ≤ 5 words apart, not inside a recorded gap. Repo wins when both hold.
4. **R-PV4 — the gate.** For `type: project`, `should_promote = birth_of(entity, siblings) is not None`; every other
   rung is ignored. Without a record the name parks on its pending line as before.
5. **R-PV5 — sections are derived on read**, six in a fixed order with their writers named on the wire; the overview
   strips the claims fence; ≤ 40 entries per section plus `more`.
6. **R-PV6 — the wire** (`PROJECT_SHAPE` g141-5): `ProjectRow.origin` from the page alone (no conversation read);
   `ProjectTimeline.origin`, `.sections`, `.people`.
7. **R-PV7 — the dry run** `api.scripts.project_origins_dry_run`: every `type: project` page, classified by
   `project_birth.classify` (stored → declared repo → named folder → cited conversations), read only.
