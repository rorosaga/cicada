# G110: automatic project continuity, slices 1–2 (plan, revision 2)

Spec (binding): [`docs/specs/2026-10-06-project-continuity.md`](../specs/2026-10-06-project-continuity.md).
Backlog: [G110](../goals/memory-evolution.md#g110), with G48 (lineage), G104 (revision safety), G105 (capture),
G149 (startup delivery), G53/G75 (the bounded entry point), G118 (evidence spans). Branch `feat/g110-continuity`, based
on `dev` a6b72f1c.

**Revision 2 (2026-10-06)** answers the plan critic's 17 findings (`CRITIQUE.md`, verdict REVISE) and applies these
orchestrator decisions:

- **Fork-prefix stripping is dropped.** Captured words are never deleted on an inferred relationship.
- **Checkout observations live in the registry** outside every bank, not in episode frontmatter.
- **Acceptance 5 is not claimed.** Lineage is recorded for G104, and an optional, bounded Sleep consumer task is offered
  separately (T10).
- **Two owner rulings are pending**, written out below as **Ruling pending (owner) A** (flush triggers) and **B** (the
  capture cap). Every task that does not depend on them can proceed now.

**Goal of these two slices.** Suppose a person opens a fresh Claude Code or Codex session in the same repository after
the last one filled, was cleared, closed or crashed. The new session should start with a short, cited note saying where
the work stopped, *before Sleep has run*. It should be able to pull more through one governed read. No recap, no save
tool, no LLM at capture.

Out of scope here:

- Cursor, Grok and remote clients (slices 3–4).
- The CLI (slice 5).

## Global Constraints

1. **No LLM anywhere on these paths.** Capture stays file I/O. The projection is string work over episode files and a
   derived index.
2. **Transcripts are read only by `transcript_capture.capture_transcript`** (G105 R2). Nothing new opens a transcript.
3. **The HTTP backend never reads a person's folder.** Only the hooks and the stdio MCP process read `.git` metadata;
   both are children of the harness, which is the authorized observer (precedent: `cicada_repo_context`,
   `mcp/server.py:1307-1327`). An import-boundary test pins this. The backend receives the hooks' observations as bytes,
   hashes the folder paths into keys, and never `stat`s them.
4. **Captured words are never deleted or rewritten because of an inferred relationship.** Lineage is metadata, and its
   strength is labeled: *delivered* (Cicada returned the note) versus *started as* (the harness said so).
5. **The ≤ 1,800-token budget applies to the whole SessionStart `additionalContext`**: header, primer, continuity block,
   the G166 reading sentence and every separator, counted with the repository's chars/4 proxy (handshake R10). The
   proxy is not a tokenizer measurement, and the plan never claims it is.
6. **R12 holds** for the final composed note and the contract: every `cicada_x(args)` they name is in the schema. The
   R12 check never runs over quoted history (the person's words), because a tool-like string inside a quote is not a
   Cicada instruction.
7. **Memory is data, never a command.** Quoted requests are labeled as history. The note tells the agent to verify the
   checkout before editing and to act only on what the person asks now.
8. **One episode per session (G104).** A new session keeps its harness-minted id, and nothing copies a source id onto
   it. The plan does not claim double consolidation is prevented beyond what is proven (see Acceptance).
9. **No Sleep stage changes**, except the optional, separately approved T10.
10. **Outside a bank, store ids, enums, hashes and times only.** The registry and ledger hold no path, title, prompt or
    exception message. Branch names are the one exception the orchestrator allowed, and only in the registry.
11. **Nothing personal in this plan, its tests or its commits.** Fixtures use `alpha-project`, `bob-example`,
    `example.com` and `/home/example/...`.
12. **Copy is provider-neutral.**
13. **Never auto-stash, reset or transfer a working tree.** The note only says to inspect.

## Rulings

### C1: the working context is assembled on demand, over a disposable metadata index

The projection is never stored. On each read, `api/services/continuity.py`:

- selects candidate sessions from **`<bank>/continuity_index.json`**, a derived, disposable, git-ignored index
  (`bank_registry.DERIVED_ARTIFACTS`) mapping every `ep_*.md` to `(mtime_ns, size, row-or-null)`;
- fully parses at most **3** chosen episodes with `markdown_parser.parse`;
- joins the registry (C4);
- renders the startup block or the `cicada_continue` text.

`_state.md` is untouched.

**How the index stays correct.** It holds no truth of its own. A row is only the head scalars of a Stop-hook episode:

- `id`, `harness`, `session_id`, `capture_kind`, `project_dir`, `captured_at`, `last_turn_at`, `processed`,
  `processed_by`.

Every lookup works like this:

1. One `os.scandir` of `episodes/`.
2. Re-read the 2 KB head of every file whose `(mtime_ns, size)` changed, filter by workspace, then sort by
   `last_turn_at`. No global mtime cut-off and no file-count cut-off before the workspace filter (finding 7).
3. Write the index back atomically.

Notes on the scan:

- Head scalars are pulled by a line regex and each value is `yaml.safe_load`ed. A head the regex cannot read
  confidently costs one full parse.
- Capture writes `last_turn_at` before `turns` (which stays the last key), so it is always inside the head.
- A missing or corrupt index is rebuilt by the same loop, with every file treated as changed.
- Freshness uses **captured activity times** (`last_turn_at`, else `captured_at`), never file mtime.

**Measured** on 1,500 synthetic episodes (300 Stop-hook sessions, each with a 500-entry `turns` sidecar and a
~127 KB file), warm OS cache, median of 7 runs. The script is in the worker's scratch folder (`bench/bench.py`); it is
not repository code.

| Step | Median | Max |
|---|---|---|
| Index load + `scandir` diff + workspace filter | 5.3 ms | 5.8 ms |
| Cold rebuild (head read + regex of all 1,500) | 41.0 ms | 43.3 ms |
| Full parse of the 3 chosen | 14.6 ms | 16.3 ms |

The critic's literal loop parsed 600 full files and took 3,243–3,302 ms (finding 6); this design avoids that. A
cold-cache measurement needs an uncached disk and is a T5 test item; the test fails above 250 ms for the full startup
path on a warm cache.

**Every stage takes the route's deadline:** the index refresh, the parse, the registry read and the render. When the
deadline is near:

- a refresh still in progress stops, and continues on a background thread;
- the block degrades to the **pointer** rendering: "a captured session exists here; `cicada_continue()`". It is printed
  only if the index already shows a candidate, so it is never invented.

`ledger: continuity=deadline`.

**Why not the alternatives:**

- *A typed episode.* Sleep would consolidate it as new evidence, which is the echo.
- *A stored tail file outside git.* It is a second copy of the session to invalidate.
- *`bank_index`.* It is process-local and cold after a restart (1–3 s, `bank_index.py:1-6`).

The index is the "disposable metadata index" the orchestrator allowed. Like the FTS and vector indexes, it is rebuilt
and never an error.

### C2: identity

**The repository is the observer's report.** At SessionStart the recall hook reads `.git` metadata and posts
`workspace: {repo_root, worktree_root, branch, head}`; the capture hook posts the same at Stop. The roots are posted
only so the backend can hash them on arrival:

- `repo_key = sha256("repo\0" + repo_root)[:16]`, where `repo_root` is the main worktree (the common dir's parent);
- `worktree_key = sha256("wt\0" + worktree_root)[:16]`.

Only the keys are stored, in the registry (C4). Matching rules:

- Two sessions are the **same repository** iff their `repo_key`s are equal.
- Nested repositories differ, because the walk stops at the nearest `.git`.
- A folder outside any checkout has no repo key. For it, and for a session captured before this plan (no registry
  row), the fallback is the episode's `project_dir`: exact string equality, or equality after folding a trailing
  `/.worktrees/<x>` or `/.claude/worktrees/<x>`. There is **no** general path-prefix join, so parent folders and
  sibling projects never merge (finding 8).

**The project page** is resolved only when asked:

- `cicada_continue(project=…)` resolves the page with `id_utils.resolve_entity_file` and matches its `repos:` paths.
  These are compared as strings in the stdio process, hashed the same way.
- If a `project` and a `path` are both given and they disagree, the tool says so and uses neither silently.
- If two pages declare the same repository, both are named.
- `_state.md` is never treated as a complete project map.

**Task.** A task is one session (one harness session id) together with the sessions Cicada delivered it to. Two
sessions in one checkout can be independent tasks, so same-cwd is **not** task identity. Selection, in order:

1. **Explicit** — `cicada_continue(session=…)` (an id of ≥ 8 characters, or an episode id).
2. **Rollover** — a candidate in the same harness and the same `worktree_key` whose registry `ended_at` is within
   **120 s** before this session's start. This is the `/clear` and "exit then start again" case. When ruling A says
   SessionEnd is not wired, rule 2 needs `ended_at` from the metadata-only end event (T4a).
3. **Single plausible** — exactly one candidate active within **2 h** of the newest candidate.
4. **Otherwise ambiguous.** The note lists ≤ 3 candidates (harness, short id, last folder segment, first line of the
   person's first request, last activity) and says: ask the person once, unless their first message says which. The
   answer is acted on with `cicada_continue(session="<id>")`, which T7 adds and R12 covers.

The tool keeps the ambiguity until a selector is given (finding 8).

**Lineage** is labeled by strength and is never declared by a third party:

- `continues: [{episode, content_hash, delivered_at, rendering}]` is stamped on the receiving session's own episode at
  its first capture. It comes from the registry's **delivery receipts** (C4). It means "Cicada returned this note to the
  harness hook". Receipt by the model is not observable and is never claimed.
- `started_as: <source>` is the harness's own SessionStart `source`.
- A fork's parent is **not** inferred. The fork's copied history is captured as the fork's own episode, so a fork is
  consolidated twice (a known gap, stated in Acceptance).
- Compatibility: Claude Code before v2.1.214 reported a fork as `resume` (critic, checked against the hook reference).

**No new double consolidation from this plan:**

- a `/clear`ed or freshly started transcript holds no source turns;
- the injected note is removed at capture by T3's exact-span stripper.

What remains open:

- An agent's paraphrase of the note is captured as agent words (finding 5): see Acceptance and T10.
- A fork's copy (above).

### C3: delivery

The block is sent at **SessionStart** only for `source ∈ {startup, clear}` or a missing source. `resume`, `compact` and
`fork` already carry their history.

The block sits inside the "From Cicada" note. Every note gains a closing line,
`recall_text.END_LINE = "(End of Cicada's note.)"`, so the capture stripper can remove exactly the note (T3).

**Budget (finding 14).** `hook_recall.compose_session_start(parts, max_tokens=MAX_TOKENS)` assembles header + primer +
block + reading sentence + separators, then measures the **whole** string. Degradation order until it fits:

1. Block: full → compact → pointer → dropped.
2. Reading sentence: dropped from this note (`READING_SEEN` is not advanced, so the first prompt still hears it).
3. **Fallback note:** header + "Cicada's primer did not fit here; `cicada_handshake` returns it." + END_LINE.

For SessionStart the primer is built with `reserve=300` (`handshake.load_or_build(…, reserve=)`, part of the cache key
and file name). `_fit`'s final branch is not trusted as a cap; the compositor is the cap. A test runs the worst-case
state through every rendering.

**Freshness and gaps** are explicit lines, never implied:

- **Captured through.** The last kept turn's role and time, from the new `tail_turns` metadata (T3). An unknown time
  prints "time not recorded".
- **Consolidation status, worded by `processed_by`:**
  - `sleep` → "consolidated by Sleep";
  - `agent`/harness → "marked processed by an agent";
  - anything else → "not yet consolidated" (finding 10).
- **Later prompt.** The registry `last_prompt_at` is after the last kept turn's time. Not printed when either time is
  unknown.
- **No captured reply.** The last kept turn is the person's.
- **Capture limit.** `capture_gap` (T3; meaning depends on ruling B).
- **May still be open.** No `ended_at`, and activity in the last 10 minutes.
- **Checkout then and now**, from the registry's observation for the source and the hook's for this session:
  - "changed since: inspect before editing" when both are known and differ;
  - "same branch and commit; uncommitted changes are not known to Cicada" only when both are known and equal;
  - otherwise "not known" (finding 12: two unknowns never print "same").

**`cicada_continue(session?, before?, project?, path?)`** is stdio only and `NEVER_REMOTE` until slice 4. It is the
governed lazy read (finding 11):

- The selected session's identity, lineage, gaps, checkout and the verify-first line. These are the **reserved**
  sections, never clipped.
- The person's requests as a numbered, dated outline.
- **Paged turn ranges**: the last turns by default, earlier ones with `before=<turn number>`. Each page carries the
  episode id and its `content_hash`; a hash that changed between pages is said.
- What agents recorded in that session.
- Omitted ranges named with the exact call that reads them.
- Lineage traversal by following a `continues` entry with `session="<episode>"`.

Output priority and the 12,000-character cap are defined in T7.

The contract (item 1) names it, so `CONTRACT_VERSION` goes to 14. A client with no hooks (Cursor today) still has the
labeled fallback.

### C4: one registry outside every bank

The file is `$CICADA_HOME/continuity/<bank-slug>-<bank-hash8>.json`, where `bank-hash8 = sha256(str(memory_path.resolve()))[:8]`.
Banks with the same name in different roots no longer collide (finding 16). Rows are keyed `<harness>:<session_id>`
and rebuilt on read **and** on write from an exact allowlist:

- `origin: {source, at}` — **immutable**; set by the first SessionStart only (finding 9).
- `starts: [{source, at}]` — lifecycle, the last 5 kept.
- `last_prompt_at`.
- `ended_at` and `ended_via` (`session_end | capture_end`). A later `resume` start clears `ended_at` and appends
  `reopened_at`.
- `deliveries: [{at, rendering, episodes: [{id, content_hash}]}]` — append-only, the last 5 kept. Recorded **by the
  route after the response is built within the deadline** (FastAPI `BackgroundTasks`), so a late worker can never
  record a delivery that was not returned. This is the furthest delivery stage Cicada can observe ("returned to the
  hook").
- `repo_key`, `worktree_key`, and `checkout: {branch, head, at, event}` — the last observation (orchestrator decision
  2).

Validation and storage rules:

- Session ids: `transcript_capture._SESSION_ID_RE`. Episode ids: `episode_ids.EPISODE_ID_RE`. Hashes: `[0-9a-f]{12}`
  and `[0-9a-f]{16}`. Times: canonical aware UTC ISO.
- Branch: ≤ 200 characters, no control characters. Head: 40 or 64 hex.
- Anything else in a stored row is dropped on read.
- Lock files are created with `os.open(…, O_CREAT|O_WRONLY, 0o600)`, JSON and temp files with mode 0600, and the parent
  directory 0700.
- A `CICADA_HOME` resolving inside a bank is refused: no registry, `registry=unavailable`.
- 30-day expiry in memory, ≤ 1,000 rows.
- Errors are enums or class names only.
- A failed write never costs a prompt. Lineage then degrades honestly: no receipt means no `continues`, and the note
  says nothing it did not observe.

### C6: the `.git` reader (finding 12)

There is one algorithm in three places, pinned by a parity test:

- `_workspace` in `api/hooks/capture.py`;
- `_workspace` in `api/hooks/recall.py`;
- `api/services/git_head.read_head` for the stdio MCP process.

An import-boundary test fails if anything under `api/routers/` or any backend-started service imports `git_head`, or
passes a request field to it. The rules:

- `cwd` must be an absolute `str` without NUL and ≤ 4,096 characters; else unknown.
- The walk goes up ≤ 8 parents. Each candidate `.git` is `os.lstat`ed:
  - a **directory** that is not a symlink, or
  - a **regular file** that is not a symlink, holding exactly `gitdir: <path>` (≤ 4 KB).
- **Linked worktree validation.** The resolved gitdir must be `<common>/worktrees/<name>`, its `commondir` file must
  resolve to that `<common>`, `<common>.name == ".git"`, and `<common>/HEAD` must exist. Anything else is unknown
  (bare repositories and submodules are out of scope and read as unknown).
- **Every file read** goes through `lstat` → must be a regular file, not a symlink → `os.open(O_RDONLY | O_NOFOLLOW |
  O_NONBLOCK)` → `read(MAX_FILE_BYTES=4096)`. A FIFO or device is never opened.
- **HEAD** is either `ref: refs/heads/<name>` with `<name>` matching `^[A-Za-z0-9._/-]{1,200}$`, with no `..` segment
  and no leading `/`, or a 40/64-hex detached head. An absolute or other ref is unknown.
- **Branch lookup:** the loose ref, under `gitdir` then `common` by joining validated components only. Then
  `packed-refs`, read once with a **byte cap of 262,144**: a file larger than the cap, or a line longer than 512 bytes,
  ends the search as unknown.
- **The returned shape is fixed:** `{repo_root, worktree_root, branch, head}`, where each field may be `None`.
- The hook's 3 s / 0.9 s request timeouts bound the whole hook. All the reader's work is bounded by bytes, so it cannot
  block on a special file.

### C7: capture-time metadata, and the metadata-only path (finding 3)

On every write, `transcript_capture` records metadata that is **not** in `content_hash`. All of it is placed before
`turns`, which stays the last key:

- `last_turn_at` — the last kept turn's time, or absent.
- `tail_turns: [{offset, speaker, at?}]` — the last **8** kept turns, with exact offsets from the capture-time turn
  list. This is the structural boundary for tails and replaces any guessing from the sidecar (finding 10).
- `turn_count` — the number of kept turns.
- `capture_gap: {dropped_turns, last_seen_at}` — only while turns were refused by the session cap; its meaning
  follows ruling B.
- `started_as` and `continues` (C2) — written once, never overwritten.

**Metadata-only update.** Before today's `unchanged` return (`transcript_capture.py:375-380`), and under the same
`episode_lock`: if the stored metadata differs from the new metadata, the frontmatter is rewritten with the **same
body**. `content_hash`, `processed` and `processed_by` are unchanged, so nothing is requeued. Sleep's retirement re-reads
under the same lock and preserves the other keys (`sleep_cycle.py:2805-2820`), so the two paths compose. The result
status is `metadata`.

### C8: injected notes are removed as exact spans

The current gaps: the prefix test only matches at a block's start, Codex skips `_HOOK_OUTPUT_RE`, and Codex's tag set
omits the hook tags (finding 4, three leaks reproduced). `transcript_extract.strip_injected(text)` therefore removes:

- each span from a line equal to one of the **exact headers** (`RECALL_HEADER`, `PRIMER_HEADER`, `READING_HEADER`)
  through the next `END_LINE`;
- a header with no `END_LINE` (a harness that truncated it), through the end of that block;
- `<session-start-hook>…</session-start-hook>` and `<user-prompt-submit-hook>…</…>` spans.

It applies to **both** harnesses' user text, and the adjacent words the person typed survive. A person who writes
*about* a note keeps their words: only an exact header line starts a span. The tests label each shape as either
**verified** (a shape a harness documents) or **assumed** (the serialization is unverified, and a live check is
listed).

## Rulings pending (owner)

### A: may PreCompact and SessionEnd also run the capture hook as a best-effort flush?

TODO ruling 7 says Stop, not SessionEnd, is *the* capture trigger. It says so because SessionEnd misses closed windows
and killed processes and has a 1.5 s budget.

- **A1 — Stop only (today).** SessionEnd and PreCompact post **lifecycle metadata only** (`ended_at`, `starts`) to
  `POST /capture/session-event`; no transcript is read on them.
  - What is lost: a turn the person interrupted (no Stop fires) and then `/clear`ed stays uncaptured. The next note
    discloses it from the registry's `last_prompt_at`.
- **A2 — Stop stays the trigger, and PreCompact and SessionEnd also run the capture hook as best-effort flushes.** The
  endpoint is idempotent by content hash. The capture log tags the event, so ruling 7's revisit signal (timeout
  `error:` lines) stays observable per event.
  - What is gained: the interrupted-then-cleared turn is captured, and the next note says "its last request has no
    captured reply" rather than "a later message was not captured".
  - Cost: one transcript read per compaction or end.
  - Stop's reliability is unchanged.

**Recommendation: A2.** It does not weaken anything ruling 7 protects: Stop remains the trigger and the flushes are
additive. It also closes the one gap a Stop-only design cannot, a mid-turn interrupt. The ruling's own revisit
condition stays measurable per event. If A1 is chosen, T4b is dropped and T4a stands.

### B: the capture cap in the context-full case

Today's limit is head-stable at 100,000 kept characters (`transcript_extract.py:55-61`): the first turns are kept, and
later turns are refused and flagged. A session long enough to fill a context window can pass it. Then the decision, the
rejection, the blocker and the next action at its end are **not in the bank**, and no flush recovers them (finding 2;
the critic's probe kept the same body after an appended correction).

- **B1 — keep head-stable; disclose only.** `capture_gap` records how many turns were refused and until when, and every
  note and `cicada_continue` says so.
  - Acceptance 1 is **not met** for an over-cap session; this slice's claim is narrowed to sessions under the cap.
  - There is no G104 impact.
- **B2 — head + tail retention.** Keep the first N characters (proposed 60,000) and the last M (proposed 40,000) of
  kept turns. The middle is dropped, with one marker line between them that is attributable to no speaker:
  `[Cicada: <k> turns between <t1> and <t2> were not kept]`, with `speaker_kind` → none.

  G104 impact, stated in full:

  1. Past the cap, every Stop changes the body. `content_hash` moves, the episode is requeued, and Sleep re-extracts
     the whole retained body each time. That is the G104 efficiency cost, now incurred by long sessions that are
     "unchanged" today.
  2. Evidence spans into tail turns that later slide out of the window become unlocatable, fall back to `reasoning`,
     and the claim stands ("provenance never blocks memory"). The head keeps its offsets.
  3. `body_revision` mismatches become more frequent while a long session is active. Sleep already leaves such an
     episode queued for the next run (A01), so the change is correct but delays consolidation.
  4. A consolidated claim from a turn that slid out loses its quote. A turn's words leave the bank when it slides out,
     which is a retention change for the person's own words.

  To reduce churn, the tail could advance in blocks of 10 turns.

**Recommendation: B2.** The primary case of the spec is a full context, and B1 makes continuity weakest exactly
there. B2's costs fall on G104's efficiency work and on the provenance of words that slide out of the middle. They
should be accepted knowingly, in G104's row, before T9 is built.

**Blocked tasks:** T9 (B2's extractor change) waits for B. T4b waits for A. Everything else proceeds. T5–T8 read
`capture_gap` and the B2 marker generically.

```python
_WT = re.compile(r"/(?:\.worktrees|\.claude/worktrees)/[^/]+$")

def fold_worktree(path: str | None) -> str:
    p = str(path or "").rstrip("/")
    return _WT.sub("", p) if p.startswith("/") else ""

def same_folder(a: str | None, b: str | None) -> bool:      # the pre-registry fallback, no prefix joining
    fa, fb = fold_worktree(a), fold_worktree(b)
    return bool(fa) and fa == fb

def repo_key(root: str) -> str: return hashlib.sha256(b"repo\0" + root.encode()).hexdigest()[:16]
def worktree_key(root: str) -> str: return hashlib.sha256(b"wt\0" + root.encode()).hexdigest()[:16]
def bank_file_id(memory_path: Path) -> str: return f"{reading_asks.bank_slug(memory_path)}-{hashlib.sha256(str(Path(memory_path).resolve()).encode()).hexdigest()[:8]}"
```

**Handler `handle_continue(session, before, project, path)`:**

**`full_text` layout, cap 12,000 characters.** Reserved sections are rendered first and never clipped; the rest fill
the remaining space in priority order:

1. **Reserved:** identity (bank; project or repository; how chosen; episode + `content_hash`; `started_as`; `continues`
   with `session="<ep>"` hints), gaps, checkout then/now, the verify-first line.
2. The last turns page, up to 6 turns, newest last (person ≤ 1,200 characters, agent ≤ 2,000).
3. The person's outline: numbered, dated, ≤ 160 characters each. When over budget the outline keeps the first 5 and
   the most recent, and names the omitted numbers.
4. **"Recorded by agents in that session":**

   - pages credited to it, from `session_stats.find_conversation(…)`. That can be `None`, and when present its
     `entity_ids` is a **set** (finding 15): `sorted(group["entity_ids"])`. It is labeled "pages built from or written

### T10 — optional: a bounded lineage consumer in Sleep (needs orchestrator approval; touches Sleep)

**Proposal.** Two narrow changes. Both are conservative, because they only *withhold* a count or a clock restart that
an echo would otherwise earn.

1. In `entity_resolver.resolve`, `episodes_seen` counts **lineage units** instead of episode ids. A unit is an episode
   plus every episode its `continues` chain reaches, within the episodes the cycle sees. It is computed by
   `sleep_cycle` from the frontmatter it already loads and passed as `unit_of: dict[str, str]`.
   - Other promotion paths are untouched: linked-to-existing, pending, substantive.
2. In `claim_reconciler._reinforce`, when **every** incoming evidence entry is `assistant` kind and its episode's unit is
   already among `existing.source_episodes`' units, `decayed_through` is not advanced.
   - Evidence and session ids are still merged, so provenance stays complete.

The person's own words (user-kind evidence) always count and always restart the clock. A genuine correction in B by the
person therefore supersedes as today.

**Why it is safe:** it can only delay a promotion that came from one work stream counted twice, or keep a silence clock
from being reset by an agent repeating itself. It never deletes, supersedes or creates anything. **Why it is optional:**
it changes Sleep (Constraint 9), and G104 owns that area.

**Tests:**

- B's agent restating A's fact gives no second-conversation promotion and no clock restart.
- The person restating it in B still counts.
- The person's correction in B still supersedes.
- Episodes without lineage behave exactly as today (the existing resolver and reconciler suites stay green).
- The T8 `xfail` turns green.

**Commit:** `feat(sleep): count a continued session's echo once (G110, G104)`
