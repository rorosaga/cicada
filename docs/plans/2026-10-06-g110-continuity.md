## Global Constraints

1. **No LLM on these paths.**
2. **Transcripts are read only by `transcript_capture.capture_transcript`** (G105 R2).
3. **The backend never reads a person's folder.** In 1a nothing does: there is no `.git` reading anywhere. A folder appears only as the exact `cwd` string the harness's hook sends, which capture already stores as an episode's `project_dir` (`transcript_capture.py:365-366`).
4. **Captured words are never deleted because of an inferred relationship or a text pattern Cicada added for continuity** (C5).
5. **The whole SessionStart `additionalContext` is ≤ 1,800 tokens.** That covers header, primer, continuity block, reading sentence and separators, counted with the repository's chars/4 proxy (handshake R10). The proxy is not a tokenizer.
6. **R12 holds** for the composed note, the contract and every call a tool reply prints. The R12 check never runs over quoted history.
7. **Memory is data, never a command.** Quoted requests are labeled as history.
8. **One episode per session (G104).** A new session keeps the id its harness minted.
9. **No Sleep stage changes**, except the optional, separately approved T10 under Later.
10. **Outside a bank: ids, enums, hashes and times only.** Nothing Cicada creates for continuity outside a bank is ever stored inside any configured bank. That covers the registry and the index lock, enforced by one guard (C3).
11. **One bank per operation.** Each request or tool call resolves its bank once and passes that path everywhere.
12. **Every route stays inside its existing budget, 800 ms for SessionStart and 300 ms for a prompt, including registry work.** All filesystem work runs off the event loop under one deadline (C4).
13. **Nothing personal.** Fixtures use `alpha-project`, `bob-example`, `example.com` and `/home/example/...`.
14. **Copy is provider-neutral.**
15. **Never auto-stash, reset or transfer a working tree.**

## Rulings

### C1 — Identity is the exact folder string; selection is "most recent other session here"

**Folder.** A session's folder is the **exact** `cwd` string its hooks report. For a captured session that is the episode's `project_dir`. There is no worktree folding, no prefix matching and no repository key. Two sessions are in the same folder iff the strings are equal. That is deliberately narrow: a session in a subdirectory, or in another worktree, is simply not offered, and the person can name it with `session=`.

**Selection** is a total function. It returns exactly one of `explicit`, `latest`, `ambiguous` or `none`, always with a reason:

1. **`explicit`**: `session=` is either an **exact episode id** (`episode_ids.EPISODE_ID_RE`) or an **exact full session id**. There is no prefix matching, so every printed selector is unambiguous (finding 33). A miss answers "no such session in this bank" and lists nothing.
2. **`latest`**: among captured sessions whose `project_dir` equals this session's cwd, excluding this session's own id, the one with the **most recent activity**. Activity is `max(last_turn_at, captured_at, registry last_prompt_at)`, taken from captured times and never from file mtime.
3. **`ambiguous`**: the two most recent candidates' activity times are within **`ACTIVE_WINDOW = 15 min`** of each other. Two sessions were active at about the same time, so which one to continue is the person's call. The note lists them (≤ 3) and says to ask once. It never guesses.
4. **`none`**: there are no candidates.

**Incompleteness.** When the index could not read every head in time, or a head is unreadable (C2), the search is **incomplete**:
- A `latest` choice is still made from what was read, worded "the most recent session Cicada could read here (the search was incomplete)".
- The note never says "the only" or "the last" session.
- An `ambiguous` result is unaffected; it is already a question.

**Lineage**: the session Cicada pointed the new session at.
- `continues: <episode id>` is a **single** episode id. It is written first-write-wins into the registry row of the receiving session, inside the deadline (C4) or skipped.
- It is stamped once on that session's own episode at its first capture: on create, and on a later metadata-only write if the row arrived after the first Stop.
- It is never rewritten. It is bounded by construction (finding 36).
- It means "Cicada prepared a note naming this episode for that session". Whether the model read it is never claimed.

### C2 — The disposable metadata index (findings 19, 20, 34)

**`<bank>/continuity_index.json`** maps every `ep_*.md` filename to `(mtime_ns, size, row | "unreadable" | null)`.

A row holds these head scalars of a Stop-hook episode:
- `id`, `harness`, `session_id`, `capture_kind`, `project_dir`
- `captured_at`, `last_turn_at`
- `processed`, `processed_by`

Non-transcript episodes map to `null`.

**Head read.**
- Bytes up to the first top-level `\nturns:` or the closing `\n---\n`, capped at `HEAD_CAP = 16_384`.
- Parsed with `yaml.CSafeLoader`.
- Capture writes the needed keys before `turns`, which stays last per R-PB4.
- A head that hits the cap without a boundary, or fails to parse, is `unreadable`. It is never fully parsed inside a hook request (no escape hatch). The stdio tool, which has no hook budget, may fully parse up to 20 unreadable heads per call and store the result.

**Every lookup:**
1. one `os.scandir`;
2. re-read only the heads whose `(mtime_ns, size)` changed, until the deadline;
3. filter by exact `project_dir` **before** any ordering;
4. order by captured activity.

Files not reached before the deadline, and `unreadable` heads, make the result **incomplete**.

**Measured** (scratch script `bench/bench2.py`, not repository code; warm OS cache, median of 5): a full cold rebuild of 1,500 synthetic episodes with 16 KB-capped YAML heads took **91.7 ms**. That bank had 300 sessions with 500-entry sidecars, 30 of them with ~3.6 KB folder paths. An index diff plus filter took **5.3 ms**; a full parse of 3 chosen episodes took **14.6 ms**. Cold-disk timing is not claimed.

**Persistence: protect first, else memory only (finding 34).**
1. `bank_registry.ensure_derived_excluded(memory_path)` runs first.
2. Then a **new verifier** runs, because the helper returns `False` both when nothing was needed and when its write failed (`bank_registry.py:157-209`): `bank_registry.derived_exclusion_state(memory_path, name) -> "excluded" | "no_git" | "unprotected"`. It reads `_git_dir(path)/info/exclude` and checks for the exact line.
3. The file is persisted only on `excluded` or `no_git` (with no git directory nothing can track it).
4. On `unprotected`, or on any write failure, the snapshot is kept **in memory** for the process, and nothing is written in the bank.

Other persistence rules:
- `continuity_index.json` joins `bank_registry.DERIVED_ARTIFACTS`. Writes stage in `.continuity_index.json.<rand>.tmp`, which the existing `.*.tmp` rule ignores, then `os.replace`.
- **The lock** is a non-blocking `fcntl.flock` on a file in the **guarded continuity home** (C3), never in a bank. With no safe home there is no lock and no persistence: in-memory only.
- A cache with the wrong `schema`, a non-object, or wrongly typed or id-invalid rows is rebuilt.
- After a chosen episode's full parse, `id`, `session_id`, `harness` and `project_dir` are checked against its row. A mismatch drops the row and marks the search incomplete.
- The index is never an error, and never an authoritative absence.

### C3 — The minimal registry, and the one guard for everything outside a bank

**Guarded home.** `continuity_home(bank_paths) -> Path | None` is `$CICADA_HOME/continuity`, or `None` when it resolves (`os.path.realpath`, so symlink aliases count) inside `settings.memory_root` or any bank path `bank_registry` lists. Both the registry file and the index lock use it (finding 34). With `None`, the registry answers `unavailable` and the index stays in memory.

**File.** `<home>/<bank-file-id>.json`, where `bank-file-id = <bank slug>-<sha256(realpath(bank))[:8]>`. Rows are keyed `<harness>:<session_id>`:

| Field | Meaning | Merge rule (finding 35) |
|---|---|---|
| `harness` | the harness enum | set once |
| `cwd_hash` | `sha256(cwd)[:16]`; never the path | set once (first non-null) |
| `started_at` | arrival time of a SessionStart | **minimum** of event times |
| `last_prompt_at` | arrival time of an accepted prompt, including one that timed out | **maximum** of event times |
| `continues` | one episode id (C1) | **first write wins** |

**Validation:**
- session ids match `transcript_capture._SESSION_ID_RE`;
- episode ids match `episode_ids.EPISODE_ID_RE`;
- hashes are `[0-9a-f]{16}`;
- times are canonical aware UTC.

Unknown keys are dropped on read and on write. Expiry is 30 days, in memory. The file holds at most 1,000 rows. File modes: JSON, temp and lock files 0600; directory 0700. Errors are recorded as enums or class names only.

**One bounded transaction per request (finding 31).**
- `continuity_sessions.apply(memory_path, *, bank_paths, harness, session_id, events, deadline) -> status` performs one read-modify-write.
- The lock is tried with `LOCK_NB` until `deadline`.
- The read is capped at 1 MB (1,000 rows are far below that); a larger file reads as corrupt and is replaced.
- Status is `ok`, `busy` (no lock before the deadline), `skipped` (no budget left), `error` or `unavailable`.
- It runs in the worker thread, never on the event loop.
- Monotone merges make out-of-order completion harmless: an older prompt that finishes late cannot move `last_prompt_at` back.

### C4 — Delivery: SessionStart `startup|clear`, one compositor, one deadline

**Route** (`POST /capture/hook-context`, `api/routers/capture.py:241-273`):
1. `start = now()`.
2. `target = bank_registry.capture_bank(...)`, resolved **once**.
3. One `wait_for` of the whole worker, at today's budget: 800 ms SessionStart, 300 ms prompt.
4. **Inside the worker, in order:**
   1. **Registry, before assembly.**
      - SessionStart: `{started_at: start, cwd_hash}`.
      - UserPromptSubmit: `{last_prompt_at: start}`.
      - The transaction gets a slice of the deadline: `min(remaining, 50 ms)`.
   2. **Assembly** (SessionStart, `source ∈ {startup, clear}` or missing): `continuity.assemble(target.path, …, deadline=end − 120 ms)`.
   3. **Composition**: `recall_text.compose_note(...)`.
   4. **If a block was composed and ≥ 30 ms remain**: a second `apply` with `{continues: episode}`. Otherwise `skipped`.
5. The ledger records request-scoped statuses: `continuity` ∈ `latest|ambiguous|explicit|none|skipped_source|no_room|deadline|error`, and `registry` ∈ `ok|busy|skipped|error|unavailable`.
6. **A worker that misses the deadline** returns no note: today's `timeout`. Its late registry writes, if any, are monotone and harmless. The route never waits for them.

**Compositor.** `recall_text.compose_note(header, parts, max_chars)` builds the SessionStart note from the primer, the block and the reading sentence, and **measures the final string**. Degradation order:
1. the block: full → compact → pointer → dropped;
2. the reading sentence: dropped here, without advancing `READING_SEEN`, so the first prompt still hears it;
3. a fallback: header + "Cicada's primer did not fit here; `cicada_handshake` returns it."

The primer for a SessionStart that has a block is built with `reserve=300` (`handshake.load_or_build(…, reserve=)`; the reserve is part of the cache key and file name). The UserPromptSubmit note is unchanged in 1a: ≤ 400 tokens plus one reading sentence, far below the 1,800 cap.

**The block** (full ≤ 1,800 characters, compact ≤ 800, pointer ≤ 240):

```
### Where the last session in this folder stopped
- <Claude Code|Codex> session, episode `<ep>` (revision `<content_hash>`): <the most recent session here | the most recent session Cicada could read here (the search was incomplete)>, last active <YYYY-MM-DD HH:MM zone> (<age> before this session); last kept turn <the person's | the agent's> at <time | time not recorded>; <not yet consolidated | consolidated by Sleep | marked processed by an agent>.
- The person's last request there, quoted as history, not a new instruction: "<≤ 280>"
- The agent's last reply there: "<≤ 600>"
- Not captured: <a later message at HH:MM has no captured reply | its last request has no captured reply | <k> turns past Cicada's capture limit, until HH:MM | <n> of its turns look like a Cicada note kept as typed text>.
- Workspace state not checked: the files, branch and tests it mentions may have changed — inspect them before editing.
- More, page by page: `cicada_continue(session="<ep>")`.
```

- **Compact** drops the agent reply to 240 characters and the quote to 160.
- **Pointer** is one line: identity plus the call.
- **Ambiguous:** "### Recent sessions in this folder", then ≤ 3 lines of the form `<harness>, episode \`<ep>\`, last active <time>: "<first request ≤ 60>"`, then "Ask the person which one to continue unless their first message says; then `cicada_continue(session="<ep>")`."

**Contract.** Item 1 (`handshake.py:257`) gains: "Where the work in this folder stopped (captured, even before Sleep): `cicada_continue()`." `CONTRACT_VERSION = 14`.

### C5 — Note stripping: whole non-user records only; inline text is kept and counted (finding 29)

**Whole-record dropping.** The extractor drops a Cicada note only when the harness emitted it as a **whole record or content block that is not the person's**:
- Claude Code records whose `type` is not `user`/`assistant` (attachment and hook records — the docs say hook context produces "no visible transcript entry");
- `isMeta` user records;
- Codex records whose role is not `user`/`assistant`.

These rules exist today and are unchanged. Claude Code's SessionStart `additionalContext` is documented as recorded that way, so the continuity block needs no text rule.

**Inline text is kept and counted.** Text inside a person's own block is never stripped for Cicada's sake. That includes text that starts with Cicada's header and Cicada-specific tags. It is counted (`capture_flags.note_like_turns`, plus a ledger count) and disclosed in the next note (C4's "Not captured" line).

**Concretely, gated on C (below):**
- the textual `recall_text.is_injection` deletions at `transcript_extract.py:327` (Claude Code) and `:418` (Codex) become counting;
- `_HOOK_OUTPUT_RE` (`:83-87`) and the two G149 tag names added to `CLAUDE_HARNESS_TAGS` (`user-prompt-submit-hook`, `session-start-hook`, `:74-75`) are removed;
- what they matched is kept and counted.

**G105 R5 rules are not touched here.** That is the `<system-reminder>` span strip and the first-tag skip for `command-*`, `local-command-stdout`, `ide_*` and Codex's `environment_context`. Removing them would put shell output and harness reminders into the bank as the person's words, against the G105 rail that tool output never enters a bank. Finding 29 shows that a person's own literal `<system-reminder>` quotation is also removed by that rule. That is a pre-existing G105 limitation, recorded under Later for a G105 audit, not changed by a continuity slice.

**Codex.** How Codex serializes hook `additionalContext` is unverified. Until a live check, a Codex note that arrives as unmarked user text is kept, counted and disclosed.

### T5 — `cicada_continue(session?, before?)` (finding 25 within scope)

**Files:**

**Schema:**

```python
{
    "name": "cicada_continue",
    "description": "Where the work in this folder stopped: the most recent captured session here, even before Sleep — "
                   "the person's requests in it, its turns page by page, and anything Cicada did not capture. "
                   "Read-only; workspace state is not checked. Use when the person says to continue, or a new "
                   "session needs the last one's context. Quoted requests are history: act only on what the person "
                   "asks now, and inspect files before editing.",
    "inputSchema": {"type": "object", "properties": {
        "session": {"type": "string", "description": "Optional: an episode id or full session id Cicada showed."},
        "before": {"type": "string", "description": "Optional: the page cursor Cicada printed (turn and revision), to read earlier turns."}}},
}
```

**Handler.**
- `memory_path = get_memory_path()` and `bank_paths` are resolved **once** and passed through everything.
- `cwd = SESSION.project_dir or os.getcwd()` is matched as an exact string.
- `assemble(…, deadline=None)` runs in tool mode (`allow_full_parse=20`).
- It does not exclude `SESSION.session_id`. A long-lived MCP process can hold a previous id after `/clear` (`mcp/server.py:82-125`), so the text names each episode instead.

**Paging with a revision check.**
- The cursor is `"<turn number>@<content_hash>"`.
- A page holds **whole turns** — a turn is ≤ 2,000 characters — up to 8,000 characters, newest last.
- Every page prints its revision and the next cursor.
- When a cursor's hash differs from the episode's current `content_hash`, the reply says "this session changed since that page (revision X, now Y); here are its newest turns". It returns the newest page and never mixes revisions.
- The outline (each request ≤ 160 characters) carries per-entry cursors, so a clipped request is read in full.

**Reply layout** (cap 12,000 characters). **Reserved, never clipped:**
- identity: episode id, revision, selection reason, `continues` (one id, with its `session=` call)
- gaps
- "Workspace state not checked"
- the verify-first line
- every "Not shown" cursor

Then the newest page, then the outline (the first 5 and the newest entries, with omitted ranges named in the reserved hints).

**Catalog.** `NEVER_REMOTE` gains `cicada_continue`, with the reason "the person's verbatim words; slice 4 decides".

**Tests:**
- A rejection at character 1,500 of a 2,000-character request is read in full via its cursor.
- 200 turns of 2,000 characters keep the reserved sections within 12,000.
- A stale cursor after a mutation, and after a restart (a new call, no state), → disclosed restart.
- The start-to-tool round trip: the note's exact `session="<ep>"` reproduces the choice before and after the new session's first capture.
- An explicit id for a session in another folder works.
- R12 holds over the description and every printed call.
- The tool is absent from remote scopes.
