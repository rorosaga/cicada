## Global Constraints

1. **No LLM on these paths.**
2. **Transcripts are read only by `transcript_capture.capture_transcript`** (G105 R2).
3. **The HTTP backend never reads a person's folder.** `.git` metadata is read only by the hooks and the stdio MCP process. Both are the harness's children, and the harness is the authorized observer; the precedent is `cicada_repo_context`, `mcp/server.py:1307-1327`. An import-boundary test pins this. The backend receives observations as data, hashes folder paths into keys at once, and never `stat`s them.
4. **Captured words are never deleted because of an inferred relationship or a text pattern.** Only spans that the harness's own envelope marks as injected are dropped (C8). Lineage is metadata, and its strength is labeled.
5. **The ≤ 1,800-token budget applies to the whole `additionalContext` of both hook events.** One compositor builds every note, reading sentence included. The count uses the repository's chars/4 proxy (handshake R10), which is not a tokenizer.
6. **R12 holds** for every composed note, the contract and every call a tool reply prints. The R12 checker never runs over quoted history.
7. **Memory is data, never a command.**
8. **One episode per session (G104).** A new session keeps the id its harness minted.
9. **No Sleep stage changes**, except the optional, separately approved T10.
10. **Outside a bank: ids, enums, hashes, times — and branch names in the registry only** (an orchestrator decision). The registry is never stored inside any configured bank (C4).
11. **One bank per operation.** Each request or tool call resolves its bank once and passes that immutable path through every stage: selection, parse, render, registry, telemetry. Nothing re-resolves the active bank mid-operation (finding 27).
12. **Nothing personal** in the plan, tests or commits: synthetic `alpha-project`, `bob-example`, `example.com`, `/home/example/...` only.
13. **Copy is provider-neutral.**
14. **Never auto-stash, reset or transfer a working tree.**

## Rulings

### C1 — On-demand assembly over a disposable metadata index, every stage bounded

The projection is never stored. On each read, `api/services/continuity.py`:

1. selects candidates from **`<bank>/continuity_index.json`**, a derived, disposable, git-ignored index;
2. fully parses at most **3** chosen episodes;
3. joins the registry (C4);
4. renders.

**The index fast path never does a full parse (finding 19).**
- Rows are refreshed from **heads**. A head is the bytes of an episode up to the frontmatter's top-level `\nturns:` key or its closing `\n---\n`, read with a hard cap of `HEAD_CAP = 16_384` bytes and parsed with `yaml.CSafeLoader` (PyYAML's C-accelerated safe loader).
- Capture writes every key the index needs before `turns`, which stays last (R-PB4). A cwd is ≤ 4,096 characters (`HookContextRequest.cwd`), so a well-formed Stop-hook head is < 10 KB.
- A head that reaches the cap without a boundary, or fails to parse, is recorded as **`unreadable`**. It is never fully parsed inside a request.
- An `unreadable` or not-yet-read file makes the search **incomplete**. It is never treated as absent.
- A bounded background worker (one per bank, 2 s per run, cancellable) retries `unreadable` heads with a full parse and fills the index for later requests.
- **Measured** on 1,500 synthetic episodes with 16 KB-capped YAML heads, warm OS cache, median of 5 runs: **91.7 ms** for a full cold rebuild. The bank had 300 Stop-hook sessions, 30 of them with ~3.6 KB folder paths containing spaces, plus `continues`/`tail_turns` metadata and a 500-entry sidecar. 0 heads were unreadable. The scratch script is `bench/bench2.py` in the worker's scratch folder, not repository code.
- Index load + `scandir` diff + filter: **5.3 ms** (r2's measurement).
- Full parse of 3 chosen episodes: **14.6 ms**.
- Cold-disk numbers need a cold disk; they are reported by T5's route benchmark as "warm OS cache" only and never claimed beyond that.

**Every stage takes the operation's deadline:** `refresh_index`, `candidates`, `view`, `turns`, `outline` and `startup_block`. When the deadline nears:
- the refresh stops (the rest continues in the background);
- no further parse starts;
- the renderer uses what is already in hand.

With an **incomplete** search, the note never claims to have found "the only" session. Selection may still pick a candidate whose choice does not depend on completeness: an explicit `session=`, or a unique rollover proven by registry events (C2). Otherwise the note renders the pointer form, naming the incompleteness.

**Index persistence (finding 20).**
- `bank_registry.ensure_derived_excluded(memory_path)` runs **before the file can first exist**, the same order as `search_index._full_build`, `search_index.py:576-580`. It writes `.git/info/exclude`, never a tracked `.gitignore`.
- `continuity_index.json` joins `bank_registry.DERIVED_ARTIFACTS`, so new banks' `.gitignore`, the exclude file and bank copy/duplicate exclusions carry it.
- Writes stage in `.continuity_index.json.<rand>.tmp`, which matches the existing `.*.tmp` rule, then `os.replace`.
- Refreshes are coordinated by a non-blocking `fcntl.flock` on `$CICADA_HOME/continuity/<bank-file-id>.index.lock`, outside the bank. A refresh that cannot take the lock reads without writing; a snapshot is complete or absent, so concurrent readers are safe.
- Exclusion is checked first (`ensure_derived_excluded` never raises). If the bank or cache is unwritable, the read path keeps the index **in memory** for the process and never errors.
- A cache with a wrong `schema` version, a non-object, wrongly typed scalars or ids failing their regexes is rebuilt, never trusted.
- After a chosen episode is fully parsed, its `id`, `session_id`, `harness` and `content_hash` are checked against the row. A mismatch, or a file changed between scan and parse, drops the row, marks the search incomplete, and moves on within the deadline.

### C2 — Identity and selection (findings 8, 23, 24)

**Repository: the observer's report.** The hooks post `workspace: {repo_root, worktree_root, branch, head}` (C6). The backend immediately derives:
- `repo_key = sha256("repo\0" + repo_root)[:16]`
- `worktree_key = sha256("wt\0" + worktree_root)[:16]`

It keeps only the keys and `{branch, head}`.

Two sessions share a repository iff their `repo_key`s are equal; nested repositories differ. When a session has no registry row (captured before this plan) or no checkout, it falls back to `continuity_keys.same_folder` on the episode's `project_dir`: exact equality, or equality after folding `/.worktrees/<x>` or `/.claude/worktrees/<x>`. There is no prefix joining.

**Which observation describes a captured revision (finding 23).** The registry keeps, per session:
- `captures`: the observation bound to each captured `content_hash` — the first observation that produced it, and the last that confirmed it unchanged;
- `latest`: the latest observation of any event.

The renderer prints:
- "**at capture**": the first observation bound to the selected episode's current `content_hash`;
- "**later seen**": `latest`, with its event and time, when it differs.

Neither is ever called "then" without that binding. If no observation is bound to the current hash, the line reads "checkout at capture: not known". A later observation can be shown, but it can never validate old results.

A session's repository for matching is the `repo_key` of its capture-bound observation. A session that later moved to another repository is matched where its captured content was produced.

**Task, and selection.** A task is one session plus the sessions Cicada returned its note to. Sessions in one checkout can be independent tasks. Selection is a **total** function: it returns exactly one of `explicit`, `rollover`, `single`, `ambiguous` or `none`, always with a reason.

1. **Explicit:** `session=` is an id of ≥ 8 characters (a prefix of a session id) or an exact episode id.
   - 1 match → chosen.
   - 0 → "no such session here".
   - ≥ 2 → listed, and the agent is asked to pick (never a guess).
2. **Rollover:** candidates in the same `worktree_key` (any harness — switching harness is the same behaviour, per the spec) whose registry `ended_at` is in `[start − 120 s, start]`. `start` is this request's arrival time.
   - Exactly **one** → chosen, "it ended just before this session started".
   - **Two or more → ambiguous** among them.
   - Unavailable when `start` is unknown, which happens only in the tool. The startup note therefore always prints the explicit call (below).
3. **Single:** exactly one candidate active within 2 h of the newest candidate, with a **complete** search. The copy states its actual age: "the only session found here; last active 3 days ago". It is never called "recent".
4. **Ambiguous:** ≤ 3 candidates are listed, with the ask-once line.
5. **None.**

The startup note **always names the selection it made as an explicit call**: `cicada_continue(session="<sid8>")`. So the lazy read reproduces the choice, whether before or after the new session's first capture, and from any MCP process. A bare `cicada_continue()` makes its own selection (rules 1, 3, 4) and says so (finding 24).

**Lineage.**
- `continues: [{receipt, episode, content_hash, rendering, strength}]` on the receiving session's episode, from the registry's receipts (C4). `strength` is `prepared` or `printed`. It is never "received", because the harness's use of a note is unobservable.
- `started_as`: the harness's own SessionStart `source`.
- No fork ancestry is inferred. A fork's copied history is captured as its own episode, so it is consolidated twice; this is a stated gap.
- Claude Code before v2.1.214 reported a fork as `resume`.

### C3 — Delivery and the whole-note budget (findings 18, 19)

**When.** The block is sent at SessionStart only for `source ∈ {startup, clear}` or a missing `source`.

**One compositor.** `recall_text.compose_note(header, parts, max_chars)` builds every note Cicada's hooks return:
- the SessionStart primer;
- the continuity block;
- the reading sentence;
- the UserPromptSubmit page note;
- each part's separator.

It measures the **final string**. Degradation order (SessionStart):
1. the block: full → compact → pointer → dropped;
2. the reading sentence: dropped here, and `READING_SEEN` is not advanced, so the first prompt still hears it;
3. a fallback note: header + "Cicada's primer did not fit here; `cicada_handshake` returns it."

For UserPromptSubmit the page note and reading sentence go through the same compositor; its order is today's page-note fit, then the reading sentence. `with_reading_note`'s post-hoc append (`hook_recall.py:540-544`) is replaced by a part. Because note stripping is now structural (C8), notes carry no in-band terminator, and the r2 `END_LINE` is withdrawn.

The primer for a SessionStart with a candidate is built with `reserve=300` (`handshake.load_or_build(…, reserve=)`). The reserve is part of the cache key and file name; the compositor, not `_fit`, is the cap.

**Gap lines** — explicit, never implied:
- the last kept turn's role and time (from `tail_turns`, C7), or "time not recorded";
- consolidation status by `processed_by`: `sleep`, agent/harness, or none;
- a later prompt: registry `last_prompt_at` after the last kept turn's time, printed only when both are known;
- no captured reply;
- the capture limit (`capture_gap`, meaning set by ruling B);
- may still be open: no `ended_at`, and activity within 10 minutes;
- the search was incomplete;
- checkout "at capture" and "later seen" (C2), and now:
  - "changed since capture: inspect before editing";
  - "same branch and commit as at capture; uncommitted changes are not known to Cicada", only when both are known and equal;
  - "not known" otherwise.

**`cicada_continue(session?, before?, expect?, project?, path?)`** is stdio-only and `NEVER_REMOTE` until slice 4. It is the governed lazy read, with full turns, revision-pinned paging and reserved hints (finding 25; T7 below). The contract (item 1) names it, and `CONTRACT_VERSION` becomes 14.

### C4 — The registry: outside every bank, written synchronously and bounded (findings 9, 21, 22, 28)

**File.** `$CICADA_HOME/continuity/<bank-file-id>.json`.
- `bank-file-id = <bank slug>-<sha256(realpath(bank))[:8]>`.
- **The file must not resolve inside any configured bank:** not inside `settings.memory_root`, and not inside any bank path `bank_registry` lists. The comparison uses `os.path.realpath`, so symlink aliases count. Otherwise `path_for` is `None`, every write answers `unavailable`, and lineage degrades.

**Rows** are keyed `<harness>:<session_id>` and rebuilt from an exact allowlist on read and on write:

| Field | Meaning | Written by |
|---|---|---|
| `origin: {source, at}` | immutable; first SessionStart only | `started` |
| `starts: [{source, at}]` | last 5; SessionStart only | `started` |
| `last_prompt_at` | arrival time of the latest accepted prompt, including ones that timed out | `prompted` |
| `ended_at`, `ended_via`, `reopened_at` | a `resume` start after an end clears `ended_at` and sets `reopened_at` | `ended`, `started` |
| `receipts: [{id, at, rendering, episodes: [{id, content_hash}], strength}]` | last 5, append-only; `strength`: `prepared` → `printed` (monotone) | `receipt_prepared`, `receipt_printed` |
| `captures: [{content_hash, first: obs, last: obs}]` | last 5; `obs = {repo_key, worktree_key, branch, head, at, event}` | `observed_capture` |
| `latest: obs` | the latest observation, any event | `observed` |

Validation:
- ids by their existing regexes (`transcript_capture._SESSION_ID_RE`, `episode_ids.EPISODE_ID_RE`);
- hashes `[0-9a-f]{12}` / `[0-9a-f]{16}`;
- receipt ids `[0-9a-f]{16}`;
- canonical aware-UTC times;
- branch ≤ 200 characters, no control characters, `/` allowed;
- head 40 or 64 hex.

Unknown keys are dropped.

**Synchronous and bounded.** Every write happens **in the route, before the response is returned**. Each takes the per-file `flock` with `LOCK_NB` retries for at most 50 ms, then a temp file plus `os.replace`. JSON, temp and lock files are 0600; the directory is 0700.
- Each write returns a **request-scoped** status (`ok | busy | error | unavailable`) that the same request's ledger row carries.
- There is no module-global counter and no `BackgroundTasks`.
- Errors are enums or class names, never messages.

**Ordering, per event (finding 22):**

| Event | Registry writes | When |
|---|---|---|
| SessionStart | `started` | always |
| SessionStart | `receipt_prepared` | when, and only when, the composed note in the response contains a block |
| UserPromptSubmit | `prompted` (arrival time) | always, including timeouts and no-note answers |
| Every hook POST that carries a workspace | `observed` / `observed_capture` | — |

The rows are independent of assembly outcome. A prompt before any start creates a row with no `origin`, never a false one.

**Receipt strength (finding 21).**
- `prepared`: written before the response leaves.
- `printed`: after printing the note to stdout, the recall hook POSTs `POST /capture/hook-ack {harness, session_id, receipt}` with a 0.2 s timeout. That is ids only, and best effort.
- Cicada never claims the model read it. A process death between the prepared write and the send leaves `prepared` — honestly unconfirmed.

**Demo redirection (finding 22).** The lifecycle endpoint (T4a) and the hook-ack resolve `bank_registry.capture_bank` exactly as the Stop hook does. While the demo is open, the end event lands in the real bank left most recently. It is listed in `test_demo_capture_routes.HANDLED_ELSEWHERE` with that reason, not answered 409.

Expiry: 30 days in memory, ≤ 1,000 rows.

### C6 — The `.git` observer: confined and time-bounded (finding 26)

There is one algorithm in three copies with a parity test: the hooks' `_workspace` and `api/services/git_head.read_head` for the stdio MCP process. An import-boundary test forbids `git_head` anywhere under `api/routers/` or any module the backend app imports.

**Confinement by directory file descriptors.**
- The start directory is opened with `os.open(cwd, O_RDONLY|O_DIRECTORY)`. This is the harness's own cwd, the trusted root; system symlinks in it, such as `/tmp`, are the harness's business.
- Every step below it is `os.open(name, O_RDONLY|O_NOFOLLOW|O_DIRECTORY, dir_fd=parent)` for a directory, or `os.open(name, O_RDONLY|O_NOFOLLOW|O_NONBLOCK, dir_fd=parent)` plus `fstat` must be `S_ISREG` for a file.
- Each name is one validated component: no `/`, not `.` or `..`, except the explicit `..` steps below.
- No path string is ever re-resolved. A symlink at **any** component — `.git`, `refs`, `heads`, a branch file, or an intermediate directory such as a symlinked `refs/heads` — fails the open and yields unknown.
- **Upward walk.** ≤ 8 steps of `openat(fd, "..")`, checking for `.git` (a directory, or a regular file) at each level.
- **A linked worktree.**
  - `.git` is a regular file `gitdir: <path>` (≤ 4 KB).
  - That path is opened once as a directory (the one place a path string is followed). It must contain a regular `commondir` whose content is exactly `../..`.
  - `common = openat(openat(gitdir_fd, ".."), "..")`.
  - `common` must contain `worktrees/<name>` whose `(st_dev, st_ino)` equals `gitdir_fd`'s, which proves containment.
  - The main worktree root is `openat(common, "..")`. Its `.git` must be a directory whose `(st_dev, st_ino)` equals `common`'s.
  - Any other layout is unknown: bare repositories, submodules, an absolute `commondir`.
- **HEAD and refs.**
  - `HEAD` (≤ 4 KB) is `ref: refs/heads/<name>`, with each `/`-separated part matching `^[A-Za-z0-9._-]{1,100}$` and the whole ≤ 200 characters, or a 40/64-hex detached head.
  - The loose ref is read by descending component by component from `gitdir_fd`, then `common`.
  - `packed-refs` is read via `fd` with a 262,144-byte cap; a longer file or a line over 512 bytes means unknown.
- **The roots posted** are `repo_root` (main worktree) and `worktree_root`, obtained as `os.path.realpath` of the cwd plus the counted `..` steps. They are strings for hashing; the backend never opens them.

**Time bound.** The observation runs in a daemon thread joined with a timeout: 0.25 s in the recall hook at SessionStart, 0.5 s in the capture hook, 1 s in the stdio tool. On timeout the hook posts `workspace: null, workspace_status: "timeout"` at once, and the thread is abandoned (the process exits after posting). The r2 claim that request timeouts bound the reader is withdrawn.

### C7 — Capture-time metadata and the metadata-only path

Unchanged from r2 except lineage and stripping. On every write, `transcript_capture` records the following before `turns`, outside `content_hash`:
- `last_turn_at`
- `tail_turns` (the last 8 kept turns, exact offsets)
- `turn_count`
- `capture_gap`
- `capture_flags` (C8)

Then lineage:
- `started_as`: attached when absent;
- `continues`: entries **appended by receipt id**. Existing entries are never rewritten, except that `strength` may rise from `prepared` to `printed`.

**The metadata-only path.** It runs under `episode_lock` before the `unchanged` return (`transcript_capture.py:375-380`). It rewrites the frontmatter with the same body whenever metadata or lineage differ: no hash change, no requeue, status `metadata`. A receipt that lands after B's first Stop is therefore attached on B's next Stop, even with an unchanged body (finding 21). Sleep's retirement re-reads under the same lock (`sleep_cycle.py:2805-2820`).

### C8 — Injected notes: drop by harness envelope only, keep and disclose otherwise (finding 18; orchestrator direction)

The extractor drops only what the **harness's own envelope** marks as not-the-person:

| Shape | Status | Rule |
|---|---|---|
| Claude Code records that are not `user`/`assistant` messages (attachments, hook entries) | verified (documented: "no visible transcript entry") | skipped by type, as today |
| Claude Code `isMeta` user messages | existing | skipped, as today |
| Claude Code `<system-reminder>…</system-reminder>` spans inside a user block | verified (documented: hook context is "wrapped in a system reminder") | the span is removed; the person's adjacent words stay |
| `<session-start-hook>` / `<user-prompt-submit-hook>` spans (both harnesses) | assumed (never observed) | the span is removed; adjacent words stay; Codex gains `_HOOK_OUTPUT_RE` |
| Codex records whose role is not `user`/`assistant` (e.g. a developer message) | structural, existing | skipped by role |
| Codex harness tags (`CODEX_HARNESS_TAGS`) as a block's first tag | existing | skipped, as today |
| **Any user-role text with no envelope**, even if it begins with or contains Cicada's header | — | **kept**. Counted in `capture_flags.note_like_turns` and in the ledger (count only). Disclosed in the next note: "N turns of that session look like a Cicada note kept as typed text; the harness did not mark them". |

**Rail amendment (orchestrator-directed, stated so the merge review sees it).**
- The textual `recall_text.is_injection` drops (`transcript_extract.py:327` for Claude Code, `:418` for Codex) become detection, not deletion.
- `CLAUDE.md`'s G149 line "a recalled note is never captured back as the person's words" becomes "a recalled note the harness marks as injected is never captured; one it does not mark is kept, flagged and disclosed — deleting the person's words is the larger harm".
- `capture-and-sleep.md` changes to match.

An echo remains possible on a harness that serializes hook context as plain user text. It is disclosed, never silent.

**Codex.** Until a live check confirms how Codex records hook `additionalContext`, Codex echo protection is **only** what its role and tags give. This is stated in the docs and in Open risks.

## Rulings pending (owner)

### A — May PreCompact and SessionEnd also run the capture hook as a best-effort flush?

- **A1:** Stop only. These events post lifecycle metadata only (T4a).
- **A2:** Stop stays the trigger. PreCompact and SessionEnd also run idempotent capture flushes, and the log is tagged per event so ruling 7's timeout signal stays visible per event.

**Recommendation: A2.** Flushes add to Stop without weakening it. They are the only way to capture a turn the person interrupted (no Stop) and then cleared. If A1 is chosen, T4b is dropped.

### B — The capture cap in the context-full case

- **B1:** keep the head-stable 100 k cap and disclose `capture_gap`. Acceptance 1 is recorded as not met for over-cap sessions.
- **B2:** keep a 60 k head and a 40 k tail, advancing in blocks of 10 turns, with a speaker-less marker for the dropped middle.

B2's G104 impact:
- requeue and whole-body re-extraction on every Stop past the cap;
- quotes in slid-out turns degrade to `reasoning`;
- more `body_revision` mismatches while a session is active;
- the person's slid-out words leave the bank.

**Recommendation: B2.** The primary case is a full context, and B1 is weakest exactly there. Its costs should be accepted in G104's row before T9.
