# G182 — installable, versioned, self-updating releases (plan and rulings)

Owner's decisions of 2026-10-05 (binding): a fresh install embeds with a small, open, ungated ONNX model and no
torch; EmbeddingGemma becomes an optional download; each bank keeps its own model. git ships inside the app. Releases
go out only when the owner promotes `dev` to `main` (`make release`, a tag, CI). No Developer ID yet: ad hoc
signatures, signed inside out and never with `--deep`. Built headless in six phases, each merged into `dev`.

## Rulings (each with its reason)

1. **Layout: `Contents/Resources/backend/`** holding `python/` (python-build-standalone 3.12, arm64), the release
   dependencies in that interpreter's own `site-packages` (so `.pth` files work without `PYTHONPATH` tricks), `app/`
   (Cicada's tracked code: `api/`, `mcp/`, `skills/`, `SKILL.md`, `VERSION`, the agent script), `git/` (dugite-native,
   pruned), `models/` and `bin/` (launchers). Mach-O under `Resources/` is signed file by file; Briefcase and py2app
   apps notarize this way. If notarization ever objects, the move is to `Contents/Frameworks` (RELEASING.md).
2. **No bytecode in the app** (~60 MB saved): the launchers set `PYTHONPYCACHEPREFIX=$CICADA_HOME/cache/pycache`, so
   Python compiles each module once, outside the signed bundle. Measured: importing `api.main` takes 2.6 s with
   bytecode and 4.0 s on the first run without; later runs read the cache.
3. **The release dependency set is a file, not an extra** (`scripts/release/requirements.in` → hashed
   `requirements.lock`, pinned to `api/uv.lock`'s versions where they overlap). `api/pyproject.toml` keeps
   sentence-transformers, so the owner's `uv sync` never drops torch. A test holds the two lists together.
4. **The model is the int8 ONNX export of `BAAI/bge-small-en-v1.5`** (34 MB; 384 dimensions; MIT; ungated): cosine
   0.997 to the fp32 export on a spot check with the same ranking, for a quarter of the size. Run by
   `api/services/onnx_embedder.py` with onnxruntime + tokenizers (no fastembed: it would add Pillow and its own
   download logic for nothing the manifest-driven runner needs). The recorded id is `BAAI/bge-small-en-v1.5`.
5. **Agents never name a path inside the app.** MCP, the hooks and the launchd plist run `~/.cicada/bin/cicada-*`,
   which the app rewrites on every launch to point at itself. A launcher whose app is gone exits 127 with a sentence
   saying to open Cicada again (a hook that fails loudly, the G182 research's gap).
6. **Two command shapes, one table on each side.** A checkout keeps `<venv python> <script>` byte for byte;
   a release uses the launchers. `api/services/runtime_layout.py` and `CicadaRuntime.swift` hold the same shapes;
   the app's allowlist accepts exactly its own runtime's shapes. The hook registry knows both forms as Cicada's own,
   so installing the app over a source install (or back) updates the one entry instead of capturing twice.
7. **The background service stays opt-in**, as onboarding and Settings already have it. A release app *refreshes* an
   existing `com.cicada.backend` plist that points anywhere but its launcher (the person already chose it); it never
   installs one unasked. `scripts/install-backend-agent.sh` stays the one source of the plist, in a release mode
   (`CICADA_BACKEND_PROGRAM`), with logs in `~/.cicada/logs`.
8. **Memory in a release defaults to `~/cicada/memory`** — the backend's own default — never inside the bundle
   (the split-brain class: the app and the backend must name the same root).
9. **The bundled git is first on the backend's `PATH`** through a wrapper that sets `GIT_EXEC_PATH` for its own call
   only; the app's own repo reads try the person's git first and the bundled one last.
10. **`CICADA_PORT`** (default 8000) is read by the backend's settings, the MCP server, the hooks, the handshake
    pointer and the app (environment, then the `cicada.port` default); the launchers bake the app's port in.
11. **A developer build never changes**: no `CicadaDistribution` stamp, so every path above is the release branch only.
    `make dev`, `install_app.sh` and the auto-updater build exactly what they built before.
