Current delivery: **19 sheet pairs, 159 tags and 1,450 frames** — Run A's ten worm sheets (including the dark menu-bar variant), plus Run B's nine room sheets. Open [preview.html](preview.html) locally for the complete art review. Read [RUN_B_REPORT.md](RUN_B_REPORT.md) for the room's acceptance evidence, remaining browser-review limitation and Run C handoff; [ROOM_TAG_TIMINGS.md](ROOM_TAG_TIMINGS.md) lists all 21 room tags. The Run A record below is preserved as historical evidence.

Run A supplies the room worm and the owner's independently drawn 18 × 18 menu-bar head. The saved Aseprite parts are the pixel authority. Run B adds the room; Run C implements the Swift player and app integration.

**Integration difference to reconcile:** this run supplies **ten** sheet pairs: the nine specified sheets plus `bookworm-small-dark`. No fixed canvas, slice or tag name changed. Select the normal coloured sheet on light menu bars and the dark sheet on dark menu bars; render with `isTemplate = false` and nearest-neighbour sampling. The dark sheet changes the physical black outline to palette white while preserving black cross pupils/lids, lime lenses, and state marks. The owner's later request explicitly allows this variant. The small `error` tremble moves the neck one pixel rather than translating the whole head, which would cut off the right lens/temple on the fixed 18-pixel canvas.

## Sources and regeneration

`parts/worm-parts.aseprite` and `parts/worm-small-parts.aseprite` contain every named component, including extra far-gaze and tail-follow-through parts. `seed_parts.lua` creates an initial version only when the part files are missing. **Do not delete the saved parts to regenerate the finished art:** that would discard the GUI corrections. `src/*.aseprite` are the assembled animation sources; sheet exports always come from these saved files.

From this directory:

```sh
BUILDS="build_worm build_worm_small" STAGE=worm tools/export_all.sh
python3 tools/make_review.py
python3 tools/make_report.py
```

The pipeline uses Aseprite 1.3.18.6-dev, full-canvas packed sheets, JSON arrays, forward tags and named slices. Authoring used Codex CLI 0.159.3 with computer use in Aseprite. Alpha is binary. No trim, smoothing, gradient or interpolated colour is used. `menubar.aseprite` is an editable alias of the normal small source, regenerated by `lua/menubar.lua` / `build_worm_small.lua`.

For a fresh trace, run `lua/trace_reference.lua` headless. It independently palette-fits and crops the owner's image and writes both 70 × 47 and 56 × 38 traces, each with a hidden original-reference layer. The 18 × 18 set is a separate redraw, never a room-worm downsample.

## GUI pixel corrections

Computer use was exercised before drawing, under the shared Aseprite lock. The reference was inspected in the GUI, and the saved part files were edited with Aseprite's native 1-pixel pencil/eraser, palette colours and onion skin. Lua builders were also run inside the GUI, then reproduced headless.

The GUI correction scripts document the native-tool strokes, rather than substituting an external image editor:

- `gui_tune_parts.lua`: upper-left temple highlight across the body variants; cleaned 3 × 3 plus pupils across the eye family; worried-brow tip; curled page pixels in flip 2/3/4.
- `gui_tune_small.lua`: the short right neck/return outline across rest, bob and droop, plus paper/seam pixels in the reading miniature.
- `gui_refine_parts.lua`: the small z diagonal; exact final-open/initial-open seam; compressed, lowered closed book that stays fully on canvas.
- `gui_final_parts.lua`: a palette-step tail follow-through pose and additional far-gaze pupils that make the attentive glance visible.
- `gui_book_swap.lua`: lowered books advance through offsets 2/4/6 and incoming books through 4/2/0, with deliberate rightward tuck. Their silhouettes compress within the canvas instead of being cut off by its bottom edge.
- `gui_z_final.lua`: removed the opposing outer end pixels from each 3 × 3 z palette version with the native 1-pixel eraser. The asymmetric short ends (`.ZZ / .Z. / ZZ.`) read as a diagonal z instead of an I-shaped block, without changing glyph size, path or timing.

The face and page turn received multiple correction passes. The z stamp and menu neck were checked again after rebuilding. Screenshots were taken through computer use at Aseprite's displayed 800% zoom. The native-tool scripts are records of those edits; their saved `.aseprite` results are authoritative.

### Saved parts and rebuild

`parts/room-parts.aseprite` holds the reusable room parts on a 110 × 64 master canvas. Each named tag is registered at its own local top-left origin. `seed_room_parts.lua` creates this file only when missing. **Keep the saved file:** it contains the native GUI corrections. The builders read its named parts, crop to the fixed prop canvases, assemble layers and slices, and save the nine `src/room-*.aseprite` sources. Exports come from those sources.

From this directory:

```sh
tools/export_all.sh
python3 tools/make_room_review.py
node tools/check_preview.mjs
```

The default pipeline rebuilds the three room builders, exports all 19 saved sources, writes the manifest, verifies all sheets and GIFs, and generates the offline HTML. **During the orchestrator's Run A freeze it deliberately skips the two worm builders.** Their sources, parts, scripts and exported bytes are unchanged. `STAGE=worm` retains Run A's explicit rebuild workflow, for its separate fix pass. No worm helper was edited. `run_checked.lua` requires a completion marker from every builder and the part checker before the shell can export; a missing marker stops the pipeline even if the authoring process returns zero.

`room-motion.json` contains the seven weather tags and integer positions/steps in play order, including the last-to-first step. Positive wraps describe periodic motion; zero means no wrap. A `.phase` element records a pose phase rather than a physical point; tree lean and curtain hem tracks record their integer offsets. Clouds and rain record physical coordinates. Leaf height resets occur behind the jamb, with both endpoint frames hidden.
